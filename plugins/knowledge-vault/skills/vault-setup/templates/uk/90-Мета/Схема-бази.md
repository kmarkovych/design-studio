# Схема vault {{product}}

## Папки
| Папка | Що тут лежить | Хто пише |
|---|---|---|
| `00-Вхідні` | сире, ще не розкладене: чернетки, ідеї, вставлені шматки. Розбирати до нуля | люди; агент — лише коли не знає, куди покласти, і каже про це |
| `10-Продукт/Архітектура` | як продукт влаштований зараз: кодові репозиторії, модулі, потоки даних, інтеграції. Хаб — [[Архітектура]] | агент knowledge-vault |
| `10-Продукт/Фічі` | одна фіча — одна нотатка: що вона робить і як. Хаб і покажчик — [[Функціональність]] | агент knowledge-vault |
| `10-Продукт/Рішення` | одне рішення — одна нотатка `YYYY-MM-DD-Назва`. Хаб — [[Реєстр-рішень]] | агент і люди |
| `10-Продукт/Глосарій.md` | терміни продукту, одне значення на термін — [[Глосарій]] | агент knowledge-vault |
| `10-Продукт/Журнал-змін` | один запис на прохід документування `YYYY-MM-DD-repoId-sha7`. Хаб — [[Журнал-змін]] | агент knowledge-vault |
| `90-Мета` | ця схема й шаблони в `Шаблони/`. Нічого машинного | люди |

Нові теки верхнього рівня — з двоцифровим номером (`20-…`, `30-…`); номери 10 і 90 зайняті.

## Агентські й власні нотатки
- **Агентська нотатка** має у властивостях `agent: knowledge-vault`. Її веде агент і може будь-коли переписати з коду.
- **Власна нотатка** — будь-яка без цього рядка. Агент її ніколи не переписує; він може лише дописати посилання на іншу нотатку в її рядок «Пов'язане:» або в список посилань.
- Хочете зберегти свої правки в агентській нотатці — приберіть рядок `agent: knowledge-vault`: з цього моменту вона ваша.

## Властивості (ключі латиницею, значення українською)
| Ключ | Де | Значення |
|---|---|---|
| `type` | усюди | одне зі списку нижче |
| `agent` | агентські нотатки | завжди `knowledge-vault` |
| `updated` | усюди, крім хаба журналу змін | дата останньої зміни `YYYY-MM-DD` |
| `sources` | агентські нотатки | список `repoId:шлях` — файли коду, з яких написано нотатку |
| `status` | `feature`, `decision` | фіча: `діє` / `вилучено`; рішення: `чинне` / `скасоване` |
| `area` | `feature`, `architecture` | область продукту, коротко |
| `date` | `decision`, `change-log` | дата рішення або проходу |
| `repo`, `from`, `to` | `change-log` | id кодового репозиторію, попередній і новий описаний коміт |
| `tags` | усюди | теми, малими літерами |

## Типи нотаток (`type`)
Список закритий: інших значень не вживати.

`hub` — точка входу в тему · `architecture` — частина устрою продукту · `feature` — фіча, як вона працює зараз · `decision` — рішення і чому · `glossary` — глосарій · `change-log` — запис журналу змін · `reference` — довідка для людей (як ця схема) · `note` — звичайна нотатка

## Правила
1. **Одна сутність — одна нотатка.** Фіча, модуль, рішення — окремими файлами.
2. **Зв'язки через `[[вікі-лінк]]`-и** найкоротшим шляхом, без розширення `.md`. У кінці нотатки — рядок «Пов'язане:» з посиланнями через ` · `.
3. **Дати абсолютні:** `2026-11-19`, ніколи «минулого тижня».
4. **Назви файлів** — українською, слова через дефіс, без дат, крім рішень і записів журналу змін.
5. **Рішення не редагують заднім числом** — нове рішення = новий файл, старому `status: скасоване`.
6. **Жодних секретів:** значень із `.env`, ключів, токенів, паролів, рядків підключення, персональних даних клієнтів, даних із продакшену. Назва змінної — можна, її значення — ні.

## Синхронізація
Vault — окремий приватний git-репозиторій. Синхронізацію робить скрипт плагіна knowledge-vault: на старті й наприкінці сесії Claude Code і кожні 15 хвилин, якщо розклад встановлено. Конфлікти він не зливає сам: скасовує rebase і попереджає.
